# 动态图标按键映射宏设计

## 目标

将现有的技能循环、CD 预测和技能组调度重写为单区域实时识别宏。程序只监控用户框选的一键技能窗口；窗口显示哪个已录入图标，就持续发送该图标绑定的按键。图标变化后，在下一次扫描立即切换到新图标对应的按键。

## 明确不做

- 不计算技能 CD、公共 CD、施法时间或网络余量。
- 不保留爆发组、基础组、优先级、循环顺序或重复次数。
- 不读取游戏内存，不注入游戏进程，不绕过反作弊。
- 不使用 OCR。
- 不恢复运行时悬浮窗。

## 配置模型

每个方案保存以下内容：

- 目标窗口标题。
- 一个相对于目标窗口客户区的共享检测区域。
- 自定义启动/停止热键。
- 扫描/按键重复间隔，默认 20ms，允许范围 10–500ms。
- 图标映射列表。每条映射包含唯一标识、启用状态、目标按键、图标特征、PNG 预览和匹配阈值。

允许多个不同图标绑定同一个按键。启动热键不得与任何已启用映射的技能按键冲突。现有旧版方案文件不删除；新版使用新的配置版本读取，旧版方案需要重新框选动态区域和录入映射，避免把旧技能栏坐标错误迁移为动态窗口坐标。

## 用户界面

主界面保留方案列表、方案名称、目标窗口、刷新窗口和保存方案。

核心区域分为三部分：

1. **动态技能窗口**：显示“框选监控区域”按钮、区域状态以及该区域最近一次截图。
2. **图标与按键映射**：以紧凑卡片或表格展示 PNG、按键、启用状态和删除按钮。添加映射时直接捕获共享区域当前图标，再选择预制按键。选中映射后可以重新捕获图标或修改按键。
3. **运行设置**：配置启动/停止热键和扫描间隔，并显示停止、未识别、已匹配某按键或目标窗口不在前台等状态。

界面删除技能库、爆发循环组、基础循环组、CD、施法、重复释放和附加可用图标等旧控件。

## 识别与发送流程

启动前必须满足：目标窗口有效、共享区域已框选、至少存在一条已启用且具有图标模板的映射、热键无冲突。

运行时每个定时周期执行：

1. 确认目标游戏窗口位于前台；否则不发送按键。
2. 只截取一次共享区域并生成特征。
3. 计算当前特征与所有启用映射模板的距离。
4. 选择距离最小且低于该模板阈值的映射。
5. 匹配成功则立即发送其按键；同一图标持续显示时，每个周期持续发送。
6. 图标变化且新模板在下一帧匹配成功时，立即发送新按键，不等待稳定帧、不等待旧图标离开、不增加 CD 或施法延迟。
7. 没有模板达到阈值时不发送，并显示“未识别”。

同一帧如果多个模板都达到阈值，只采用距离最小者，确保每个周期最多发送一个按键。输入发送通过现有 Windows `SendInput` 队列完成。

## 图标录入

用户先框选共享检测区域。添加映射时程序隐藏主窗口，短暂让游戏画面稳定，然后捕获该共享区域的 PNG 和多帧特征，以多帧平均值生成模板并自动计算容差阈值。录入后立即在映射列表显示 PNG 预览。

若两个映射模板过于相似，保存时给出冲突提示，要求重新捕获或删除其中一条，避免运行时随机选择。

## 性能与故障处理

- 默认 20ms 周期；如果一次处理尚未结束，不重入、不堆积定时任务。
- 每周期只有一次区域截图，模板比较全部在内存中完成。
- 目标窗口失效、截图失败或输入发送失败时自动停止并显示错误。
- 目标窗口暂时不在前台时保持运行但暂停发键，回到前台后立即恢复扫描。
- 删除方案或映射前要求确认；停止程序时保存当前方案。

## 测试范围

- 匹配器选择距离最近且达到阈值的映射。
- 未达到阈值时不产生按键。
- 同一图标连续多帧时每个周期都产生同一按键。
- 图标由 A 变为 B 时下一周期立即切换为 B，不经过稳定帧或冷却门槛。
- 一周期最多选择一个映射。
- 禁止启动热键与技能按键冲突。
- 配置序列化可完整保存共享区域、间隔、PNG 和映射。
- 旧版配置不会被破坏或误当作新版配置运行。
- WPF 界面构建、完整单元测试和 win-x64 发布均通过。
