# 单图标来源与手动优先打断设计

## 目标

在现有动态技能图标识别方案上增加两项能力：

1. 用户可以单独框选一个技能图标，并把它追加到当前图标按键映射中。
2. 用户可以为每个方案配置多个手动优先按键。自动识别运行时，真实按下这些按键会立即暂停自动截图与按键发送；最后一个按键松开后等待 1 秒再自动恢复。

不改变动态图标区域、现有批量技能来源扫描和图标匹配算法。

## 单个技能来源框选

区域设置增加“框选单个技能”按钮。操作流程如下：

1. 确认当前方案已经选择目标游戏窗口。
2. 主窗口暂时隐藏，用户在游戏客户区内框住一个完整技能图标。
3. 程序直接使用该框选区域生成预览、签名和完整像素模板，不执行技能网格分割。
4. 新图标追加到当前待保存映射列表，原有批量或单个图标均保留。
5. 新图标初始为未绑定状态，用户沿用现有“点击按键按钮后直接按键”的操作完成映射。
6. 如果新图标与列表中已有图标达到重复判定标准，则不追加，并提示已存在。

单图标框选不修改方案的 `SourceX/SourceY/SourceWidth/SourceHeight`，也不替换批量技能来源区域。只有点击“保存全部映射”后，新映射才写入方案文件。

## 手动优先打断键配置

主窗口底部设置区增加“优先打断键”列表和“添加按键”按钮：

- 点击“添加按键”后直接按下目标按键完成绑定，交互与技能映射、启停热键一致。
- 每个已绑定按键显示为紧凑标签，并提供删除按钮。
- 支持现有预制按键范围：`F1-F12`、`0-9`、`A-Z`、`~`。
- 自动去重，同一个打断键只保存一次。
- 打断键允许与技能映射按键相同，使用户的真实手动操作优先于程序模拟输入。
- 打断键不得与当前方案的启停热键相同，保存时进行校验。

方案模型新增 `InterruptKeys: List<string>`。该字段随正常保存、复制、新建、导入和导出处理。旧方案缺少字段时按空列表加载，不需要迁移或重新配置。

## 运行时行为

程序使用 Windows 低级键盘钩子监听物理键盘事件，并始终把事件继续传递给系统和游戏：

1. 忽略带 `LLKHF_INJECTED` 标记的程序模拟按键，防止自动发送触发自身暂停。
2. 仅当识别正在运行、目标游戏位于前台且按键属于当前方案的 `InterruptKeys` 时接受新的按下事件；已经记录为按住的键即使游戏随后失去前台，也仍处理其松开事件，避免暂停状态残留。
3. 任一打断键按下时立即进入手动优先状态；后续自动扫描周期在截图和发送前直接返回。
4. 使用集合记录当前仍被按住的打断键，重复的键盘自动连发不会增加计数。
5. 只有最后一个打断键松开时才开始 1 秒恢复计时。
6. 恢复计时期间再次按下任一打断键，会取消原恢复时间并继续暂停。
7. 1 秒结束后，自动识别从下一个扫描周期正常恢复，不补发暂停期间错过的按键。
8. 停止识别、切换方案或关闭程序时清空按住状态和恢复时间，避免状态泄漏到下一次运行。

手动优先状态不会把方案切换为“已停止”，浮窗的启停状态仍保持运行。主窗口状态文字可显示“手动优先，松开后 1 秒恢复”，便于诊断。

## 组件边界

- `MacroProfile`：保存 `InterruptKeys`。
- `ProfileInputValidator`：校验按键范围、去重结果和启停热键冲突。
- 单图标捕获流程：复用 `RegionSelectionWindow`、`WindowsSkillCaptureService.CaptureRegion`、`PixelIconTemplateBuilder` 和现有待保存映射模型。
- `ManualInterruptGate`：纯状态组件，负责按下集合、最后松键后的恢复截止时间和当前是否暂停，便于单元测试。
- `PhysicalKeyboardMonitor`：封装 `WH_KEYBOARD_LL`，过滤注入事件并发布物理键按下/松开事件；不包含业务规则。
- `MainWindow`：协调配置界面、监听生命周期、前台窗口判断和自动扫描门控。

## 错误处理

- 未选择有效游戏窗口时，单图标框选沿用现有窗口错误提示。
- 框选取消时不修改任何映射。
- 框选区域过小、截图失败或模板无效时提示失败，不追加空卡片。
- 捕获到重复图标时显示提示，不改变原映射。
- 键盘钩子安装失败时禁止启动识别并显示明确错误，避免用户误以为手动打断已生效。
- 保存时若打断键与启停热键冲突，阻止保存并提示具体按键。

## 测试

- 单图标捕获转换为待保存映射，并保留完整像素模板。
- 单图标追加不覆盖已有映射，重复图标会被拒绝。
- 一个打断键按下立即暂停，松开后不足 1 秒仍暂停，满 1 秒恢复。
- 多个打断键同时按住时，只有最后一个松开才开始恢复计时。
- 恢复等待期间再次按下会重新进入持续暂停。
- 重复 `KeyDown` 不会导致一次 `KeyUp` 后永久暂停。
- 注入按键被监听器忽略，物理按键事件继续传递。
- 停止、切换方案时门控状态被清空。
- 配置 JSON 往返和旧方案缺省字段兼容。
- 校验拒绝打断键与启停热键冲突，允许打断键与技能映射键相同。
- 完整解决方案测试、Release 发布和安装包构建通过。
