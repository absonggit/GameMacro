# 闭环技能状态检测设计

## 目标

在不使用 OCR、不读取游戏内存、不绕过安全机制的前提下，通过游戏窗口内技能图标的视觉状态确认技能是否就绪及是否成功进入冷却，避免固定时间、网络和输入延迟造成循环漂移。

## 标定

每个启用技能保存相对游戏客户区的检测矩形，以及相同尺寸的“就绪”和“冷却”参考特征。用户依次执行“框选区域”“记录就绪”“记录冷却”。界面只显示标定状态，不在技能卡片展示图标。

## 状态判定

截图缩放为固定小尺寸，转换为抗整体亮度变化的归一化灰度特征。当前特征分别与就绪、冷却参考计算均方差；距离更小且领先幅度达到阈值时才形成候选状态，否则为未知。连续三帧就绪或连续两帧冷却才确认，未知帧清除连续计数。

## 自动释放状态机

固定 CD 只限定最早检测时间。最高优先级且本地 CD 到期的技能连续三帧就绪后发送按键。发送按键不启动技能 CD；程序进入最长“施法时间 + 800ms 网络余量”的确认阶段。连续两帧冷却后才确认释放成功，以确认时刻启动固定 CD；后续按键锁定至从实际按键时刻计算的“施法时间 + 1秒公共CD”结束。确认超时则视为失败，不启动技能 CD；重新等待就绪并重试。

## 安全与异常

目标窗口不在前台、最小化、客户区尺寸无效、检测区域越界或技能未完成双状态标定时，不发送按键并显示原因。截图失败不改变任何计时状态。F12 始终停止自动循环。

## 测试

单元测试覆盖特征比较、歧义状态、连续帧防抖、就绪触发、冷却确认后计时、确认超时不计时、公共锁和优先级。发布后执行完整测试、Release 构建和桌面程序启动冒烟测试。
