# 批量技能图标分割与按键映射设计

## 目标

保留现有“动态一键技能窗口”的单区域实时监控。重做映射录入：用户另外框选一块包含多个技能图标的区域，程序从截图中自动识别并分离每个有效技能图标，忽略空槽，然后让用户为每张图标设置按键映射。

## 输入与布局

批量来源区域可以包含一排或多排图标；不要求用户输入行数、列数、图标数量或固定间距。图标需具有近似方形的可见槽位或图案边界。程序按实际视觉内容检测候选图标，并按从上到下、从左到右排序。

空槽不生成映射。相同图标在一次扫描中只保留一份。检测遗漏时允许用户单独框选一个图标补充；误识别结果可以在保存前删除。

## 分割流程

1. 捕获用户框选的技能来源区域。
2. 将 BGRA 图像转换为亮度图并计算水平、垂直边缘强度与局部纹理方差。
3. 通过边缘连通区域生成近似方形候选框，不使用固定网格切割。
4. 合并高度重叠或相互包含的候选框，过滤尺寸过小、长宽比异常和纹理不足的区域。
5. 对候选框内部进行有效内容检查；低亮度且低纹理的空槽被丢弃。
6. 将有效候选框按坐标排序，生成待绑定图标卡片。
7. 使用标准化签名比较候选项，合并视觉距离低于重复阈值的重复图标。

检测器只依赖项目现有 .NET 图像数据，不引入 OpenCV、模型文件、OCR 或网络服务。

## 图标标准化与运行匹配

技能来源图标与动态窗口可能具有不同边框、尺寸和按键文字。所有映射模板与运行时动态截图在生成特征前执行同一标准化处理：

- 按相对比例裁掉外围槽位边框。
- 忽略底部按键文字区域。
- 保留中央技能图案主体。
- 通过现有相对网格签名生成与像素尺寸无关的特征。

运行时仍然只扫描原有动态窗口。匹配成功后每个扫描周期持续发送对应按键；图标变化后下一次成功匹配立即切换按键。分割功能只用于配置阶段，不进入运行循环。

## 用户界面

现有动态区域卡片保持不变。映射区域改为：

1. “框选并扫描技能”按钮：打开区域选择器并捕获整块技能来源区域。
2. 来源区域预览：显示用户框选的完整截图和检测到的有效图标数量。
3. 待绑定卡片区：每张卡片显示自动分离的图标、预制按键下拉框和删除按钮。
4. “手动补充图标”：单独框选遗漏图标并追加到待绑定区。
5. “保存全部映射”：校验按键选择和模板冲突后，用待绑定卡片整体替换当前方案的映射列表。
6. “重新扫描”：重新框选并生成新的待绑定列表，但在点击保存前不破坏已经保存的运行映射。

待绑定项默认不猜测按键，必须由用户选择。允许多个不同图标绑定同一个按键。

## 数据模型

方案增加可选的技能来源区域坐标和完整来源截图，仅用于界面预览与重新编辑。待绑定列表是界面编辑状态，不自动写入运行映射。点击“保存全部映射”后，每项生成现有 `IconKeyMapping`，保存标准化签名、PNG 预览、按键、启用状态和匹配阈值。

旧的单张逐次捕获映射继续能够读取和运行；用户执行一次批量保存后即可换成新模板，不删除旧方案文件。

## 错误与补救

- 未选择目标窗口或批量框选区域无效时不开始扫描。
- 没有检测到有效图标时保留原映射并提示重新框选或使用手动补充。
- 检测到疑似空槽或重复图标时直接过滤，并在状态区显示过滤数量。
- 用户删除误识别卡片只影响待绑定列表。
- 未选择按键的卡片会阻止“保存全部映射”，并高亮提示。
- 保存后的映射如果与另一模板过于相似，阻止保存并指出冲突卡片。

## 测试范围

- 从合成截图中检测大小不同、间距不同和多行排列的方形图标。
- 不依赖固定行列数。
- 过滤低纹理空槽、过小噪声和异常长宽比区域。
- 合并重叠候选框和重复技能图标。
- 输出顺序稳定为从上到下、从左到右。
- 标准化后，带不同底部按键文字或不同边框的同一图案仍能匹配。
- 手动补充可以追加单个标准化模板。
- 批量扫描失败或取消时不覆盖已经保存的映射。
- 批量保存完整序列化按键、PNG、签名和阈值。
- 原有持续发键、即时切换、热键冲突和前台窗口限制测试继续通过。
- Release 全量测试、win-x64 发布和 GUI 冒烟检查通过。
