# Windows 游戏键鼠宏设计规格

## 1. 目标与边界

构建一个仅用于 Windows 的桌面宏编辑器。用户通过图形界面手动配置技能规则，程序在目标游戏位于前台且总开关开启时，根据固定间隔或画面冷却状态发送键盘输入。

程序提供完整 C# 源码，并发布为可直接运行的 Windows `.exe`。

程序只使用普通 Windows API，包括屏幕截图、全局热键、前台窗口判断和 `SendInput`。不提供驱动级输入、进程内存读写、反作弊规避或其他隐藏注入机制。用户需自行确认目标游戏规则是否允许使用宏。

## 2. 技术路线

- 平台：Windows
- 语言与界面：C#、.NET、WPF
- 图像处理：OpenCvSharp
- 配置格式：JSON
- 输入方式：Windows `SendInput`
- 全局热键与窗口管理：Win32 API
- 发布形式：源码和单文件 Windows 可执行程序

选择 WPF 是因为它适合实现原生 Windows 桌面界面、拖放排序、透明区域框选和实时状态绑定。C# 也能直接访问全局热键、前台窗口和输入 API。

## 3. 核心使用流程

1. 用户新建或选择一个宏方案。
2. 用户选择目标游戏窗口。
3. 用户添加技能规则，并为每条规则指定按键、运行模式和参数。
4. 对于冷却检测规则，用户在游戏画面上框选技能图标区域，随后在实时预览中调整检测阈值。
5. 用户拖动技能卡片确定释放优先级。
6. 用户保存方案并设置全局总开关；默认建议 `F8`，但允许修改。
7. 开启后，程序只在目标游戏是前台窗口时运行规则。
8. 再次按总开关关闭当前方案；全局紧急停止键立即停止全部规则。

## 4. 界面设计

界面只参考用户提供的游戏内“战斗辅助设置”布局，不复刻其美术素材、字体或装饰。程序采用简洁现代暗色风格。

### 4.1 左侧：方案列表

- 展示所有宏方案。
- 支持新建、选择、重命名、复制和删除。
- 显示方案名称和启用状态。

### 4.2 右上：技能优先级队列

- 以技能卡片横向排列，并支持拖动排序。
- 卡片显示图标或区域缩略图、绑定按键、运行模式、启用状态和实时就绪状态。
- 支持新增和删除技能规则。
- 冷却检测规则参与优先级仲裁；固定间隔规则以循环标记显示并独立调度。

### 4.3 右下：条件与参数编辑器

- 编辑当前选中规则的按键、模式、间隔、检测区域、检测方式、阈值和触发保护时间。
- 支持“全部满足”与“任一满足”条件组合。
- 首版条件包括：技能图标就绪、目标窗口位于前台、区域颜色条件和模板图片条件。
- 提供“框选检测区域”功能：主窗口暂时隐藏，透明遮罩允许用户在游戏画面上拖选区域。
- 实时展示区域截图、检测分数以及“就绪/冷却”判断结果。

### 4.4 顶部与底部

- 顶部：方案名称、目标窗口选择、导入、导出。
- 底部：当前运行状态、总开关、紧急停止键、最近触发技能和简短运行日志。

## 5. 规则模型

每条技能规则具有以下数据：

- 唯一标识与显示名称。
- 是否启用。
- 绑定的键盘按键或鼠标动作。
- 运行模式。
- 优先级。
- 运行条件集合及组合方式。
- 固定间隔或检测轮询间隔。
- 触发后的保护时间。
- 屏幕检测区域，以目标窗口客户区的相对坐标保存。
- 检测方式与阈值。
- 可选的参考模板图片。

首版支持两种运行模式：

1. 固定间隔：总开关开启后按设定间隔持续发送动作，直到关闭或暂停。
2. 条件释放：持续检测画面；条件满足时进入优先级仲裁并发送一次动作。

## 6. 检测与执行逻辑

### 6.1 运行门控

只有同时满足以下条件才允许发送动作：

- 当前方案总开关已开启。
- 目标游戏窗口存在、未最小化且为前台窗口。
- 当前规则已启用。

游戏失去焦点时立即暂停发送动作；再次成为前台窗口后自动继续检测与执行。

### 6.2 冷却检测

- 默认每 75ms 截取一次所需的技能区域，用户可在合理范围内调整轮询间隔。
- 检测方式支持亮度/饱和度特征、区域颜色条件和模板相似度。
- 每条规则保存独立阈值，并通过实时预览校准。
- 判断结果必须连续稳定达到配置次数后才视为就绪，避免单帧噪声误触发；默认连续两次。

### 6.3 优先级释放

- 条件型规则按队列从左到右排列，左侧优先级最高。
- 当多个技能同时就绪时，只触发优先级最高的一条。
- 触发后进入可配置的公共间隔，再重新截图和判断，不沿用触发前的就绪结果。
- 每条技能另有独立触发保护时间，避免同一冷却周期内重复触发。

### 6.4 固定间隔规则

- 固定间隔规则与条件型规则可以同时运行。
- 每条固定间隔规则拥有独立计时器，不参与技能优先级仲裁。
- 所有输入最终通过统一发送队列串行发送，避免同一时刻产生冲突输入。

### 6.5 停止语义

- 总开关按一次开启当前方案，再按一次关闭。
- 紧急停止键拥有最高优先级，并停止所有规则。
- 停止、退出或异常时，程序释放所有由自身保持为按下状态的键盘键和鼠标键。

## 7. 模块边界

### 7.1 编辑器与视图模型

负责方案、技能卡片、条件编辑、参数校验和实时状态展示。它只操作领域模型和服务接口，不直接调用输入或截图 API。

### 7.2 执行引擎

负责生命周期、规则调度、条件判断、优先级仲裁、暂停、取消和输入串行化。执行引擎不依赖具体 WPF 控件。

### 7.3 Windows 平台服务

负责 `SendInput`、全局热键、窗口枚举、前台窗口识别、客户区坐标转换和屏幕截图。所有平台调用集中封装，便于隔离测试。

### 7.4 图像检测服务

负责从截图提取特征、执行模板匹配、计算检测分数和返回结构化结果。它不负责决定是否发送输入。

### 7.5 配置服务

负责方案 JSON、模板图片、导入导出、原子保存和最近有效配置恢复。

## 8. 数据流

1. 全局热键服务通知执行引擎切换运行状态。
2. 执行引擎检查目标窗口状态。
3. 截图服务根据规则中的窗口相对区域获取图像。
4. 图像检测服务返回每条规则的分数与就绪状态。
5. 执行引擎对条件型规则进行优先级仲裁，并合并到固定间隔规则的待执行动作。
6. 统一输入队列通过 `SendInput` 串行发送动作。
7. 运行事件回传界面，用于状态灯、最近触发记录和日志显示。

## 9. 配置与文件

- 每个宏方案使用版本化 JSON 模型保存。
- 检测区域保存为目标窗口客户区相对坐标，降低窗口移动造成的影响。
- 模板图片保存在方案资源目录中；导出时与 JSON 一起打包。
- 保存采用临时文件加原子替换，避免程序中断造成配置损坏。
- 发现配置损坏时保留原文件，并尝试恢复最近一次有效副本。

## 10. 异常处理

- 找不到目标窗口：暂停方案并提示，不向其他窗口发送输入。
- 窗口最小化或失去焦点：暂停输入，恢复前台后继续。
- 截图失败或区域无效：跳过受影响规则并记录错误，其他规则继续。
- 全局热键冲突：拒绝保存冲突设置并要求重新绑定。
- 图像模板丢失：禁用相关条件并在界面标记。
- 配置损坏：保留损坏文件并恢复最近有效配置。
- 未处理异常：先停止引擎并释放输入，再记录错误和显示提示。

## 11. 测试与验收

### 11.1 自动化测试

- 配置序列化、版本和导入导出往返测试。
- 条件组合与优先级仲裁单元测试。
- 固定间隔调度、取消和触发保护测试。
- 使用固定截图样本测试冷却与就绪识别。
- 使用伪造窗口、截图和输入服务测试前台门控及异常路径。

### 11.2 手工验收

- 全局总开关能可靠启停，紧急停止始终有效。
- 固定间隔规则按设定频率运行。
- 第一排技能能够区分冷却和就绪。
- `F1`、`F2`、`F3`、`F4` 按队列优先级释放，同时就绪时只发送最高优先级技能。
- 同一技能不会在一帧或同一保护期内重复触发。
- 目标游戏不在前台时不发送任何动作。
- 保存、重启、导入和导出后配置一致。
- 发布包中包含源码说明和可直接运行的 `.exe`。

## 12. 首版非目标

- 不录制用户实时键鼠操作。
- 不读取或修改游戏进程内存。
- 不提供驱动级输入或反作弊规避。
- 不支持后台窗口输入；目标游戏必须在前台。
- 不自动识别任意游戏界面；技能区域与阈值由用户配置和校准。
- 不实现脚本语言、网络同步、云方案市场或远程控制。

## 13. CD 整数识别增量设计

当前阶段暂缓自动按键，优先完成可观察、可校准的技能 CD 倒计时识别。

### 13.1 识别目标

- 只识别技能图标中央的整数倒计时，范围为 1–3 位数字。
- 不识别小数、文字或其他游戏数值。
- 连续两帧识别到相同整数后，才更新界面显示。
- 连续两帧没有识别到有效数字时，将技能状态显示为“就绪”。
- OCR 结果不会在本阶段触发任何键盘或鼠标输入。

### 13.2 技能图标

- 用户完成区域框选后，程序立即截取该区域并保存为 PNG。
- PNG 文件按方案与规则 ID 命名，保存在本地方案资源目录。
- 技能优先级卡片显示保存的真实技能图标。
- 重新框选时覆盖旧图标；图标丢失时显示默认占位图，不影响重新框选。

### 13.3 OCR 流程

1. 在目标游戏窗口可见时，每 200ms 截取一次技能区域。
2. 从技能区域中取中央数字候选区，避免底部快捷键文字干扰。
3. 将候选区放大 4 倍并转为灰度图。
4. 使用对比度增强与二值化突出浅色倒计时数字。
5. 使用 Tesseract 英文数字模型识别，并将字符白名单限制为 `0123456789`。
6. 清除非数字字符，只接受 1–3 位且大于 0 的整数。
7. 通过连续两帧稳定器生成最终 CD 状态。

### 13.4 界面反馈

- 每张技能卡片显示技能图标、绑定按键以及当前 CD。
- 有稳定数字时显示例如 `47 秒`。
- 无稳定数字时显示绿色“就绪”。
- 识别尚未稳定或截图失败时显示“识别中”，而不是错误地显示就绪。
- 参数区提供单次“测试 OCR”，展示原始识别文本、解析结果和预处理图片，便于定位框选与字体问题。

### 13.5 依赖与错误处理

- 使用 Tesseract OCR NuGet 库和随程序发布的英文 `eng.traineddata`。
- 启动时验证模型文件；缺失时明确提示 OCR 资源缺失。
- 单个技能截图或 OCR 失败只影响该技能，并在卡片上显示“识别失败”。
- 关闭监控或退出程序时取消全部截图任务并释放 OCR 引擎与图像资源。

### 13.6 验收标准

- 框选后，技能卡片能显示对应的真实图标。
- 对用户截图中类似 `47` 的整数倒计时，测试 OCR 能返回 `47`。
- 倒计时变化时，卡片在两帧稳定后更新整数。
- 数字消失两帧后，卡片显示“就绪”。
- OCR 监控期间不发送任何游戏按键。

## 14. 混合 CD 与施法时间增量设计

由于实际技能 CD 会受到装备急速、Buff、减 CD 和重置效果影响，系统采用“本地估算 + OCR 校正”，不使用纯手动固定计时作为唯一依据。

### 14.1 技能参数

每条技能规则增加：

- 基础 CD，单位秒，允许一位小数，范围 0–600 秒。
- 施法时间，单位秒，允许一位小数，范围 0–30 秒；瞬发技能填写 0。
- 是否启用手动按键监听。

### 14.2 本地计时

- 只在目标游戏位于前台且 CD 监控已开启时监听技能键。
- 监听到与规则绑定的物理按键后，立即从基础 CD 开始本地倒计时。
- 同时开始施法锁定计时；施法时间大于 0 时，该技能卡片显示“施法中”。
- 施法锁定只记录状态，不拦截用户输入，也不自动发送其他技能。
- 本地倒计时使用单调时钟计算结束时间，避免界面刷新延迟累计误差。

### 14.3 OCR 校正优先级

- OCR 连续两帧识别到相同整数时，用该整数校正本地剩余 CD。
- OCR 读到的整数是画面权威值，可覆盖基础 CD 估算。
- OCR 暂时无结果时，本地倒计时继续，不立即标记就绪。
- OCR 连续两帧无数字，且本地倒计时已经归零时，才显示“就绪”。
- 技能重置导致数字提前消失时，连续无数字状态可将本地 CD 提前归零，但必须经过可配置的短确认窗口；首版使用 400ms。

### 14.4 卡片显示

- 识别或估算出的剩余整数直接覆盖显示在技能图标中央。
- CD 数字不再显示在按键文本旁边。
- 就绪时图标中央显示“就绪”。
- 施法期间图标使用高亮边框，并显示“施法中”。
- OCR 原始文本与黑白预处理图仍保留在诊断区。

### 14.5 输入边界

- 使用普通 Windows 低级键盘钩子只读监听物理按键。
- 不屏蔽、不修改、不重放用户按键。
- 不使用驱动级监听，不绕过反作弊。
- 当前阶段不通过程序自动释放技能。

### 14.6 验收标准

- F1 规则配置基础 CD 10 秒后，用户在游戏前台按 F1，卡片从 10 开始倒计时。
- 配置施法时间 1.5 秒后，按键触发后的 1.5 秒内卡片显示“施法中”。
- OCR 稳定识别到 7 时，本地剩余时间校正为 7 秒。
- OCR 短暂失败时倒计时不中断。
- 数字叠加在技能图标中央。
- 监听过程不发送、阻塞或修改任何键盘输入。

## 15. 最终精简覆盖规则

本节覆盖第 6 节中的画面检测、第 13 节以及第 14.3 节的 OCR 校正规则。最终版本不包含任何 OCR 或屏幕检测能力。

- 用户为每条技能手动填写基础 CD 与施法时间。
- 目标游戏位于前台且监控开启时，物理技能键按下立即开始固定 CD 和施法计时。
- 技能图标中央显示剩余整数；施法期间显示“施法中”；归零显示“就绪”。
- 保留已保存的技能图标路径；没有图标时显示占位区域。
- 删除 OCR、亮度阈值、检测区域、框选区域、测试检测、校准按钮和诊断预览。
- 删除 Tesseract、`tessdata`、System.Drawing 截图依赖以及所有 OCR 运行任务。
- 急速、Buff、减 CD 与技能重置不会自动修正计时，用户需要修改基础 CD 参数。
- 只读键盘监听不拦截、不修改、不重放按键，不调用 `SendInput`。

验收：配置 F1 基础 CD 56.78 秒、施法时间 1.8 秒并开启监控；游戏前台按 F1 后，卡片先显示“施法中”，随后显示向下取整展示的剩余整数，归零后显示“就绪”。

## 16. 自动优先级循环覆盖规则

本节将第 15 节的只读手动计时扩展为标准 Windows 输入自动循环。

- F8 开启或关闭自动循环；F12 立即停止。
- 仅当目标游戏位于前台时发送按键。
- 每次调度从启用规则中按优先级升序选择第一个已就绪技能。
- `SendInput` 成功后，立即启动该技能的固定 CD、配置的施法时间以及全局公共 CD。
- 全局公共 CD 固定为 1 秒，并在施法时间结束后继续计算；下一个技能等待时间为 `施法时间 + 1秒`。
- `SendInput` 失败时不启动任何计时，并暂停自动循环显示错误。
- 技能卡片删除图片，只显示技能名称、大号绑定按键和剩余整数/施法中/就绪。
- 不使用 OCR、截图、进程内存、驱动注入或反作弊绕过。

验收：F1 优先级 1、F2 优先级 2 且均就绪时先发送 F1；随后至少等待 `F1施法时间 + 1秒公共CD`；F1 未就绪而 F2 就绪时发送 F2。
