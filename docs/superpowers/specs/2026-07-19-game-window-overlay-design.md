# 指定游戏窗口方案浮窗设计

## 目标

为当前目标游戏窗口提供一个紧凑控制浮窗，显示当前方案名称和识别状态，并允许在停止状态切换同一游戏进程的方案。运行状态禁止切换，保证任何时刻只有一个方案控制识别和按键发送。

## 交互

- 浮窗显示当前方案名称、`已停止/运行中` 状态、方案选择和启动/停止按钮。
- 运行中禁用方案选择；停止后才允许切换。
- 切换方案同步主窗口选择，但不自动启动新方案。
- 只列出与当前方案绑定到相同目标进程的方案；没有进程名时按窗口标题匹配。
- 主窗口提供“显示游戏浮窗”开关，按方案保存。

## 窗口行为

- 仅当目标游戏窗口位于前台，或用户正在操作浮窗本身时显示。
- 切到桌面、IDE 或其他进程时自动隐藏。
- 浮窗无任务栏按钮、保持置顶，默认位于目标游戏客户区左上角。
- 停止状态允许拖动；位置以目标客户区相对坐标保存到现有 `OverlayLeft/OverlayTop`。
- 游戏窗口移动或改变尺寸后，浮窗按保存的相对坐标重新定位。

## 状态架构

- `MainWindow` 仍是唯一运行状态所有者，继续维护唯一的识别计时器。
- `GameOverlayWindow` 只发送“选择方案”“切换运行”“位置变化”事件，不创建识别器或输入服务。
- 主窗口每次状态变化都向浮窗刷新方案名、运行状态和可切换状态。
- 方案切换复用主窗口现有选择流程，确保识别器缓存、热键和预览同时更新。

## 验证

- 同目标进程方案会出现在浮窗；其他进程方案不会出现。
- 运行中拒绝切换；停止后切换成功且不会自动运行。
- 保存和恢复浮窗相对位置。
- 主窗口与浮窗启动/停止状态始终一致，且只有一个识别循环。
