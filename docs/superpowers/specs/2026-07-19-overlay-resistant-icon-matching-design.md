# 动态图标黑色渐变抗干扰匹配设计

## 背景

长期运行时，F3 与 `~` 技能会发生混淆。现有方案中的 F3 模板本身保存正常，并且两套方案间的 F3 模板距离稳定；但 F3 与 `~` 是全部模板中最接近的一对。动态技能区域右上角还存在技能来源图片中没有完全一致的黑色渐变和状态叠加，使运行帧的亮度、边缘与颜色分布发生偏移，最终可能让两个候选的排名反转。

## 目标

- 动态区域带右上角黑色渐变、轻微缩放或亮度变化时，仍应把 F3 识别为 F3。
- 不因放宽阈值而把未知图标或 `~` 错识别为 F3。
- 不改变方案 JSON 格式，不要求用户重新扫描图标或重新绑定按键。
- 保持当前 10ms 扫描间隔下的低资源占用。

## 方案

继续使用现有的 32×32 像素模板和候选排名流程，只增强 `PixelIconTemplateMatcher` 的距离计算：

1. 使用固定稳定区域掩码，忽略动态槽位右上角容易出现黑色渐变、层数或状态标记的区域；现有底部按键文字裁剪保持不变。
2. 结构比较继续使用均值归一化相关性，减少整体亮暗变化的影响。
3. 在稳定区域内增加梯度方向直方图，区分 F3 的多条平行斜线和 `~` 的宽弧形轨迹。方向特征只描述边缘方向，不依赖具体亮度。
4. 最终距离由结构、边缘强度、颜色比例和方向特征组合得到。
5. 保留最大距离和第一名领先第二名的双重保护；不添加 F3 专属规则，也不降低全局安全门槛。

## 数据流

运行帧截图 → 现有中心裁剪与 32×32 缩放 → 对每个已启用模板执行位移容错比较 → 应用稳定区域掩码 → 计算结构/颜色/边缘方向距离 → 候选排序与置信差检查 → 发送对应按键。

## 测试

- 新增回归场景：平行红色斜线图标作为 F3，弧形红橙轨迹作为 `~`，运行帧在右上角叠加黑色渐变后仍选择 F3。
- 反向场景：带相同渐变的 `~` 仍选择 `~`。
- 未知图标仍被拒绝。
- 保留现有位移、缩放、快速切换和相似候选保护测试。
- 运行 App 与 Core 全量测试，并重新生成安装包。

## 非目标

- 不引入 OCR、机器学习模型或全屏搜索。
- 不保存多个运行时模板。
- 不修改动态区域框选、方案导入导出或按键发送逻辑。
